# AI Agent Reliability Audit — Delivery Checklist

## Before accepting work

- [ ] One workflow is clearly identified.
- [ ] Decision-maker and technical owner are known.
- [ ] Intended external state is understandable.
- [ ] Evidence can be supplied safely.
- [ ] Audit is not being misrepresented as certification or penetration testing.
- [ ] Scope, exclusions, price and delivery date are written.

## Before evidence access

- [ ] Credentials are explicitly prohibited or separately governed.
- [ ] Data minimisation and redaction have been discussed.
- [ ] Approved evidence location and reviewers are recorded.
- [ ] Retention and deletion dates are recorded.
- [ ] Provider/tool spend ceiling is written.
- [ ] Production mutation is disabled unless separately approved.

## During the audit

- [ ] Preserve raw evidence before interpretation.
- [ ] Separate agent claims from observed state.
- [ ] Record inaccessible or uncertain facts rather than guessing.
- [ ] Test realistic partial, retry, rollback and false-success cases.
- [ ] Keep actor, observer and final-verdict authority distinct.
- [ ] Stop on access, integrity, privacy or spending boundary violations.

## Before delivery

- [ ] Every confirmed finding cites evidence.
- [ ] Severity and confidence are separate.
- [ ] Strengths that should be retained are recorded.
- [ ] Repairs have observable acceptance evidence.
- [ ] Unsupported universal claims are removed.
- [ ] Implementation work is separated from the audit.
- [ ] Private evidence has not entered public material.

## After delivery

- [ ] One factual-review round is completed or disputes are recorded.
- [ ] Evidence is retained or deleted according to agreement.
- [ ] Any testimonial/case-study wording is separately approved.
- [ ] Follow-on work has a new written scope.
- [ ] Lessons are added to deterministic regression cases where safe.
