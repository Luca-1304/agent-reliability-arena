# AI Agent Reliability Audit — Delivery Pack

The audit service now has a reusable, fixed-boundary operating pack:

1. [`AI_AGENT_RELIABILITY_AUDIT.md`](AI_AGENT_RELIABILITY_AUDIT.md) — public service definition.
2. [`AUDIT_INTAKE_TEMPLATE.md`](AUDIT_INTAKE_TEMPLATE.md) — qualification and safe initial information.
3. [`AUDIT_SCOPE_TEMPLATE.md`](AUDIT_SCOPE_TEMPLATE.md) — written workflow, access, spend and delivery boundary.
4. [`AUDIT_EVIDENCE_REQUEST.md`](AUDIT_EVIDENCE_REQUEST.md) — minimal, redacted evidence request.
5. [`AUDIT_REPORT_TEMPLATE.md`](AUDIT_REPORT_TEMPLATE.md) — evidence-led findings and implementation report.
6. [`AUDIT_REMEDIATION_ACCEPTANCE.md`](AUDIT_REMEDIATION_ACCEPTANCE.md) — post-repair verification.
7. [`AUDIT_DELIVERY_CHECKLIST.md`](AUDIT_DELIVERY_CHECKLIST.md) — operational quality and privacy checklist.
8. [`AUDIT_OUTREACH_PLAYBOOK.md`](AUDIT_OUTREACH_PLAYBOOK.md) — bounded client-acquisition and learning loop.

## Governing rules

- One workflow per initial engagement.
- Fixed scope and price before work.
- Representative or redacted evidence preferred.
- No credentials or unrestricted production access during ordinary intake.
- No production mutation or provider spending without separate written approval.
- Agent self-report is not completion evidence.
- Uncertainty is labelled rather than guessed.
- Implementation is scoped separately.
- No certification, penetration-test or universal-reliability claim.
